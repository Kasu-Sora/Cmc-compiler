1. 一般表达式的代码、长度/count、临时槽和 lookup 模型已经在 call 库中存在，本例通过 binary-finish 库复用该闭包。先核对实际定义及 helper BODY 合同，再补构造子观察和可选后缀；不要复制整套模型或把既有证明重复计费。
2. 局部 entailment 若需保持 `pc==pc@pre`、`temp==temp@pre`，必须从建立该断言时的存储事实把它们带入前件。仅在后件添加相等式会生成包含无约束 pre 变量的假命题。本例五处转换先被独立 VC 审查拒绝，补全前件后再验证。statement 引用同名 goal 常量时，声明文本相同不代表 goal 定义未变；应比较展开后的目标与新增事实来源。
3. 本例的构造子转换需要同时保留局部变量单元、节点七个字段及子节点所有权。存在量的开合放在同一量词作用域内；透明的 `cm_expr_shape` 仅包装等式，帮助避免过早替换破坏资源匹配。曾尝试删除“冗余”事实但丢失局部单元，已撤回，不能把该简化当作成功经验。
4. 左／右值分支和短路 op 的纯事实与代码后缀必须对应。原 `op=0 ∨ op=1` 可在整数域改写为等价区间 `0<=op<=1`，但不能把任意 op 的接口整体缩窄。只在具体分支将 `cm_short_value`、opcode 和实际常量归一化。
5. 结果类型的引用良构由 `cm_typed_program`、参数/局部 slot 良构和 `cm_expr_wf` 做结构归纳推出；不能额外加进用户函数前提。PC 中间界由既有精确代码长度/count 等式与非负性得到；临时槽界由构造子的 max 预算投影得到，嵌套 call 的非负性可复用参数链表计数/深度定理。
6. 精确指令列表证明常需显式展开 `cm_expr_code_for`，再化简 `Z.eqb`／`Pos.eqb` 和 list 拼接。`cbn` 未必展开目标 wrapper；闭合 opcode 常量还可计算后用算术或判别关闭。先检查实际剩余目标，避免把资源匹配问题误判为规格缺口。
7. `Intros`／预处理可能已提取非空与零值事实，甚至关闭整个分支。只对剩余目标使用取消、算术和 `Goal_apply`；本例曾因继续处理已关闭分支而失败。节点重组需逐项消去匹配字段，单次 `cancel` 未必处理完全部资源。
8. 整文件任务必须覆盖六个 static helper 和公共 dispatcher，并在合并后做完整检查。同文件递归前向声明与 BODY、跨 call/expr 的假定接口与实现合同分别核对；匹配合同补齐模块化实现依赖，不自动产生终止性、跨模块链接或 TVM 保持性元定理。
9. 公共成本以最终合并库为准。本例保留了独立组产生的若干同义类型引用／临时槽非负引理，全部计入新增成本，不能按语义去重后隐去工作量。后续可在控制器允许的已验证公共快照中复用；不要为压缩计量而在验收后改写证明库。流程状态竞争造成的重试另作基础设施记录，不当作数学证明修复。
