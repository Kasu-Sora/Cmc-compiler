1. 互递归函数的前向声明和 BODY 必须采用同一完整契约；既有 helper 接入契约逐项对照已验证 BODY，保留任意 `done`、`tail`、loop 标志和跳转界。
2. 用透明构造子投影连接各局部标注中的 AST 逻辑值；QCP 局部 existential 名字不能跨标注作用域直接复用。投影必须在对应 kind/构造子事实下使用，默认分支不能成为新增假设。
3. 资源展开与折叠成对维护未改变参数的局部栈单元。本例六处仅修复折叠端仍会在展开端丢失资源；在两端保留相同 `@pre` 桥后，全部相关 VC 通过。函数参数值不变不等于其栈资源自动存在。
4. count helper 返回值与数学计数相等时，显式规范化同一局部 cell，再连接容量和 PC 事实。先复用表达式/原语长度定理，再对语句结构归纳；从代码列表长度导出非负性，避免把目标结论加入输入契约。
5. AST 资源开闭直接复用 `cm_stmt_rep_node`。明确指定要重写的父节点，检查 sepcon 结合形式；`Intros` 可能已经提取纯事实，预处理也可能已经关闭目标，后续 tactic 应只作用于剩余目标。
6. 公共增量按最终合并库计量：本例计划中的一条长度引理最终形成四条已证明 helper，不能用候选池或初始计划数量代替最终成本。源侧同名 helper 若先前为 static，此次导出仍需按实际依赖闭包计费。
7. 保留检查失败与基础设施重试的区别。本例一次 exact 命令遇到 controller stale-state 写入拒绝，沿用同一 owner 和绑定命令重试后通过；不修改 controller state 或用新 run 绕过。
